# 发布与回滚

本文件记录《灵素》的发布流程、回滚步骤与发布后抽查清单，供每次发版执行。

## 1. 发布流程

1. **本地全量验证**（全部通过才可发布）：

   ```bash
   npm run test              # 单元/组件/真库测试
   npm run lint              # ESLint
   npm run typecheck         # vue-tsc 类型检查
   npm run validate:content  # 内容校验
   npm run build             # 生产构建（确认无 >500kB 主 chunk 警告）
   npm run test:coverage     # 覆盖率门禁（domain ≥90% / store ≥80%）
   ```

2. **同步文档**：更新 `CHANGELOG.md`、`docs/维护与迭代计划.md`、`docs/MVP验收清单.md` 中的版本与测试基线。

3. **打 tag**（保留上一版本构建产物与历史）：

   ```bash
   git tag vX.Y.Z
   ```

4. **推送到远程**：

   ```bash
   git push origin main --tags
   ```

5. **CI 自动执行**：`ci.yml` 在 push 后自动跑 lint/typecheck/validate:content/coverage/build/e2e；`deploy-pages.yml` 在 main 分支 push 后自动构建并部署到 GitHub Pages（`https://jitangliyoubolizha.github.io/lingsu/`）。

6. **发布后 24h 内抽查**：按第 3 节清单逐项检查。

## 2. 回滚步骤

GitHub Pages 部署的是 `main` 分支 HEAD 的构建产物。回滚即让 `main` 指回上一稳定版本。

**方案 A（推荐）：revert 问题提交**

```bash
git revert <问题提交 hash>      # 生成反向提交，保留历史
git push origin main
```

**方案 B：切回上一 tag 并重新发布**

```bash
git checkout v上一版本号         # 回到上一 tag
git checkout -b hotfix-rollback  # 新建分支
git push origin hotfix-rollback:main   # 需要临时放开 main 保护（若有）
# 或：在 main 上 git reset --hard v上一版本号 后 git push --force（不推荐，会改写历史）
```

**回滚后**：确认线上站点恢复、上一版本 tag 仍可检出；随后在新分支修复问题再走正常发布流程。

## 3. 发布后 24h 抽查清单

- [ ] 首页可打开，底部导航四项正常
- [ ] 条文列表 → 条文详情（原文/译文/注解/相关方剂/上一条下一条）
- [ ] 方剂列表 → 方剂详情（组成/剂量参考/煎服法/类方关系/安全提示）
- [ ] 药物详情（出现方剂反查）
- [ ] 全文搜索（条文/方剂/药物三类结果）
- [ ] 刷题（随机/按篇/按题型/待巩固）
- [ ] 每日任务与错题本
- [ ] 收藏（详情页收藏 → 我的收藏分组展示）
- [ ] 我的页（学习计划管理/字号三档/数据备份导出导入）
- [ ] 免责声明全文页可访问
- [ ] PWA 可安装、离线可打开主要页面
- [ ] 内容纠错与意见反馈入口可用
