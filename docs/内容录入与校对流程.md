# 内容录入与校对流程

> 版本：v0.1
> 配套：`docs/数据规范.md`、`docs/内容校验脚本规格.md`
> 用途：规范《伤寒论》等内容的录入、校对、来源记录与验收流程。

---

## 1. 目标

- 保证内容可追溯、可校对、可校验；
- 避免“白话译文/注解来源不明”“剂量换算无依据”等问题；
- 让内容录入从“人工随意添加”变成“可检查的流程”。

---

## 2. 录入流程

### 2.1 总流程

```
选材 → 录入 → 自检 → 校对 → 校验脚本 → 合入
```

1. **选材**：确定底本、篇目、条文范围；
2. **录入**：按 `docs/数据规范.md` 的 YAML 格式填写；
3. **自检**：录入者按本文档 checklist 自检；
4. **校对**：至少一名校对者复核原文、译文、注解；
5. **校验脚本**：运行 `npm run validate:content`，全部通过；
6. **合入**：内容修改与代码修改分开提交。

---

## 3. 单条文录入 Checklist

每条条文合入前必须满足：

- [ ] 原文与底本一致，简体；
- [ ] 条文 ID 正确且唯一；
- [ ] 白话译文为项目自行编写，不照抄现代教材；
- [ ] 至少 1 条公版注解，注明书名、作者；
- [ ] 相关方剂 ID 存在；
- [ ] 症状标签全部来自 `symptom-terms.yaml`；
- [ ] 无禁用词（诊断、治疗方案、推荐用药等）。

---

## 4. 方剂录入 Checklist

每首方剂合入前必须满足：

- [ ] 方名、类方归属正确；
- [ ] 组成药物 ID 全部存在；
- [ ] 原书剂量照录原文；
- [ ] 剂量换算有依据，按中医药大学研究数据计算，并标注学术争议；
- [ ] 相关条文 ID 存在；
- [ ] 类方/加减关系目标方剂存在；
- [ ] 固定安全提示完整。

---

## 5. 校对状态

内容文件头部或记录中可标记校对状态：

| 状态 | 含义 |
|---|---|
| `draft` | 初稿，未校对 |
| `reviewed` | 已人工校对 |
| `published` | 已通过校验并合入 |

> MVP 内容合入时至少为 `reviewed`。

---

## 6. 版权与来源记录

每个数据文件头部注释必须记录：

- 底本来源；
- 原文版本；
- 古注作者与书名；
- 白话译文为“项目自编”；
- 剂量换算参考来源（中医药大学研究数据，具体出处上线前标注）。

示例：

```yaml
# 来源：宋本《伤寒论》（明·赵开美复刻宋本系统）
# 译文：项目自编，待校对
# 注解：成无己《注解伤寒论》等公版注家
# 剂量换算：按中医药大学研究数据，具体出处待标注
```

---

## 7. 校勘记录

遇到原文异文或标点分歧时，在条文 `notes` 或单独校勘记录中写明：

- 分歧内容；
- 采用版本；
- 依据；
- 记录人/日期。

---

## 8. 验收标准

- [ ] `npm run validate:content` 通过；
- [ ] 无孤儿引用、无缺译文、无缺注解；
- [ ] 所有译文达到 `reviewed` 状态；
- [ ] 版权来源信息完整；
- [ ] 剂量换算依据明确。
