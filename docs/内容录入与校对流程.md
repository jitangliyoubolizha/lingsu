# 内容录入与校对流程

> 版本：v0.2
> 配套：`docs/数据规范.md`、`docs/内容校验脚本规格.md`
> 用途：规范《伤寒论》等内容的录入、来源记录与验收流程；校对后置，以用户反馈持续纠错。

---

## 1. 目标

- 保证内容可追溯、可校验、可修订；
- 结构性问题（来源不明、引用断裂）由校验脚本强制拦截；
- 正确性问题按产品方决定采用“先上线、用户反馈纠错”，专业人工校对后置。

---

## 2. 录入流程

### 2.1 总流程

```
选材 → 录入 → 自检 → 校验脚本 → 合入（校对后置，见 §5）
```

1. **选材**：确定底本、篇目、条文范围；
2. **录入**：按 `docs/数据规范.md` 的 YAML 格式填写；
3. **自检**：录入者按本文档 checklist 自检；
4. **校验脚本**：运行 `npm run validate:content`，全部通过；
5. **合入**：内容修改与代码修改分开提交；
6. **纠错（后置）**：上线后收到用户反馈 → 核对 → 修订 → 重新过校验脚本 → 合入，并在 `校对记录.md` 登记。

---

## 3. 单条文录入 Checklist

每条条文合入前必须满足：

- [ ] 原文与底本一致，简体；
- [ ] 条文 ID 正确且唯一；
- [ ] 白话译文为项目自行编写，不照抄现代教材；
- [ ] 至少 1 条公版注解，注明书名、作者；
- [ ] 相关方剂 ID 存在；
- [ ] 症状标签全部来自 `symptom-terms.yaml`；
- [ ] 无禁用词（诊断、治疗方案、推荐用药等）。

---

## 4. 方剂录入 Checklist

每首方剂合入前必须满足：

- [ ] 方名、类方归属正确；
- [ ] 组成药物 ID 全部存在；
- [ ] 原书剂量照录原文；
- [ ] 剂量换算有依据，按中医药大学研究数据计算，并标注学术争议；
- [ ] 相关条文 ID 存在；
- [ ] 类方/加减关系目标方剂存在；
- [ ] 固定安全提示完整。

---

## 5. 校对状态

内容文件头部或记录中可标记校对状态：

| 状态 | 含义 |
|---|---|
| `draft` | 初稿，未人工校对（**允许发布**，靠用户反馈纠错） |
| `reviewed` | 已人工校对 / 用户反馈修正确认 |
| `published` | 已通过校验并合入 |

> 产品方决定（2026-08-19）：MVP 及后续内容以 `draft` 合入发布，专业人工校对后置；发布门槛为「结构校验通过 + 免责声明醒目 + 反馈渠道可用」。

---

## 6. 版权与来源记录

每个数据文件头部注释必须记录：

- 底本来源；
- 原文版本；
- 古注作者与书名；
- 白话译文为“项目自编”；
- 剂量换算参考来源（中医药大学研究数据，具体出处上线前标注）。

示例：

```yaml
# 来源：宋本《伤寒论》（明·赵开美复刻宋本系统）
# 译文：项目自编，待校对
# 注解：成无己《注解伤寒论》等公版注家
# 剂量换算：按中医药大学研究数据，具体出处待标注
```

---

## 7. 校勘记录

遇到原文异文或标点分歧时，在条文 `notes` 或单独校勘记录中写明：

- 分歧内容；
- 采用版本；
- 依据；
- 记录人/日期。

---

## 8. 验收标准

- [ ] `npm run validate:content` 通过；
- [ ] 无孤儿引用、无缺译文、无缺注解；
- [ ] 所有译文达到 `draft` 及以上（`reviewed` 随人工校对/反馈修订推进）；
- [ ] 版权来源信息完整；
- [ ] 剂量换算有依据或显著标注"依据待标注/存疑"（专业校对后置）。
