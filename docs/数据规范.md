# 《灵素》内容数据规范

> 版本：v0.1（草案，待 M0 内容录入前确认）
> 状态：与 `docs/PRD.md`、`docs/开发规范.md` 配套；本文档是 `content/` 数据源的唯一字段级规范。
> 冲突处理：数据字段与文件组织以本文档为准；文档维护规则以 `docs/开发规范.md` 为准。

---

## 1. 目标与范围

1. 定义 `content/` 下所有学习内容数据的目录结构、文件格式、字段、ID 规则与校验规则。
2. 当前范围：`content/shanghanlun/`（《伤寒论》宋本）。
3. 未来新增书籍时，按“书 → 版本 → 篇 → 条文”的四层结构新增目录，不修改既有数据。

---

## 2. 目录与文件组织

```
content/
└─ shanghanlun/
   ├─ book.yaml              # 书元数据
   └─ sb/                    # 版本代码：宋本
      ├─ edition.yaml        # 版本元数据 + 篇目清单
      ├─ chapters/           # 条文数据，按篇拆分，可分段
      │  ├─ taiyang-shang.yaml
      │  ├─ taiyang-zhong-1.yaml
      │  ├─ taiyang-zhong-2.yaml
      │  └─ ...
      ├─ formulas.yaml       # 方剂
      ├─ herbs.yaml          # 药物
      ├─ symptom-terms.yaml  # 症状/脉象/病机术语表
      └─ questions.yaml      # 人工复核题（自动生成题不落盘）
```

- 数据源使用 **YAML**，字段统一使用 **snake_case**。
- TypeScript 层由 loader 转换为 camelCase 类型，字段映射表在 `src/data/types.ts` 中维护。
- 所有内容文件在构建期自动校验，校验失败则构建失败。

## 3. ID 规则

### 3.1 通用格式

```
<书代码>.<版本代码>.<实体代码>
```

| 实体 | 格式 | 示例 |
|---|---|---|
| 条文 | `书.版.篇代码.NNN` | `SHL.SB.TYS.001` |
| 方剂 | `书.版.F.NNN` | `SHL.SB.F.001` |
| 药物 | `书.版.H.NNN` | `SHL.SB.H.001` |
| 症状术语 | `书.版.SYM.NNN` | `SHL.SB.SYM.001` |
| 人工复核题 | `书.版.Q.NNNN` | `SHL.SB.Q.0001` |

- ID 一旦发布**不得更改**，即使名称或内容修正。
- 条文号 `NNN` 使用三位数字，题号使用四位数字。
- 页面显示仍为“篇名·第 N 条”，内部 ID 只用于程序引用。

### 3.2 篇代码表

| 篇名 | 代码 |
|---|---|
| 辨太阳病脉证并治上 | `TYS` |
| 辨太阳病脉证并治中 | `TYZ` |
| 辨太阳病脉证并治下 | `TYX` |
| 辨阳明病脉证并治 | `YM` |
| 辨少阳病脉证并治 | `SY` |
| 辨太阴病脉证并治 | `TAI` |
| 辨厥阴病脉证并治 | `JUE` |
| 辨霍乱病脉证并治 | `HUO` |
| 辨阴阳易差后劳复病脉证并治 | `YI` |

## 4. 实体定义

### 4.1 书元数据 `book.yaml`

```yaml
code: SHL
name: 伤寒论
description: 东汉张仲景著，中医经典著作
editions:
  - code: SB
    name: 宋本
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | string | 是 | 书代码，全局唯一 |
| `name` | string | 是 | 书名 |
| `description` | string | 否 | 一句话说明 |
| `editions` | array | 是 | 本书包含的版本代码列表 |

### 4.2 版本元数据 `edition.yaml`

```yaml
code: SB
book: SHL
name: 宋本
source: 明·赵开美复刻宋本系统
chapters:
  - code: TYS
    name: 辨太阳病脉证并治上
    order: 1
    files:
      - chapters/taiyang-shang.yaml
  - code: TYZ
    name: 辨太阳病脉证并治中
    order: 2
    files:
      - chapters/taiyang-zhong-1.yaml
      - chapters/taiyang-zhong-2.yaml
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | string | 是 | 版本代码 |
| `book` | string | 是 | 所属书代码 |
| `name` | string | 是 | 版本名 |
| `source` | string | 是 | 底本来源说明 |
| `chapters` | array | 是 | 篇目清单；`files` 按顺序合并为该篇全部条文 |

### 4.3 条文数据（章节文件）

章节文件可包含一个或多个章节；同一篇可拆成多个文件，构建时按 `chapter.code` 合并。

```yaml
chapter:
  code: TYS
  name: 辨太阳病脉证并治上
  order: 1
  part: 1        # 可选：拆分文件序号
  part_total: 1  # 可选：该篇总文件数
clauses:
  - id: SHL.SB.TYS.001
    no: 1
    text: 太阳之为病，脉浮，头项强痛而恶寒。
    translation: 太阳病的提纲证，表现为脉浮，头痛项强，怕冷。
    annotations:
      - source: 伤寒论注
        author: 成无己
        text: 恶寒者，卫气不温也。
    formulas:
      - SHL.SB.F.001
    symptom_tags:
      - SHL.SB.SYM.001   # 发热
      - SHL.SB.SYM.002   # 脉浮
      - SHL.SB.SYM.003   # 恶寒
    study_tags:
      - 太阳病提纲
    notes: 可选备注
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 条文 ID，全局唯一 |
| `no` | integer | 是 | 篇内条文序号 |
| `text` | string | 是 | 原文，简体 |
| `translation` | string | 是 | 白话译文，1 段 |
| `annotations` | array | 是 | 至少 1 条；普通条文 1 家，重要条文 2–3 家 |
| `annotations[].source` | string | 是 | 书名/注本名 |
| `annotations[].author` | string | 是 | 作者 |
| `annotations[].text` | string | 是 | 注解原文 |
| `formulas` | array | 否 | 相关方剂 ID 列表 |
| `symptom_tags` | array | 否 | 结构化术语 ID 列表，术语必须存在于 `symptom-terms.yaml` |
| `study_tags` | array | 否 | 学习提示词/关键词，自由文本 |
| `notes` | string | 否 | 内部备注，不展示 |

### 4.4 方剂数据 `formulas.yaml`

```yaml
formulas:
  - id: SHL.SB.F.001
    name: 桂枝汤
    category: 桂枝汤类
    composition:
      - herb: SHL.SB.H.001
        dose: 三两
        note: 去皮
    original_dose_text: 桂枝三两（去皮） 芍药三两 甘草二两（炙） 生姜三两（切） 大枣十二枚（擘）
    dose_reference: 教材通行换算参考，一两约合今 3g；古今剂量存在学术争议，非用药指导。
    decoction: 上五味，㕮咀三味，以水七升，微火煮取三升，去滓，适寒温，服一升。
    related_clauses:
      - SHL.SB.TYS.001
      - SHL.SB.TYS.012
    related_formulas:
      - relation: 加减方
        target: SHL.SB.F.002
        note: 桂枝加葛根汤
    safety_notice: 仅供学习研究，不构成医疗建议，请勿自行用药。
    # 以下字段可选；缺省时由系统自动推导（见第 5 节）
    main_symptoms: []
    pulse: []
    pathomechanism: ""
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 方剂 ID |
| `name` | string | 是 | 方名 |
| `category` | string | 是 | 类方归属，如“桂枝汤类” |
| `composition` | array | 是 | 药物组成；`herb` 必须存在 |
| `composition[].dose` | string | 否 | 原书剂量文本 |
| `composition[].note` | string | 否 | 炮制/去法等备注 |
| `original_dose_text` | string | 否 | 整段原书剂量/煎服前文字 |
| `dose_reference` | string | 否 | 古今剂量参考，必须含学术争议提示 |
| `decoction` | string | 否 | 原书煎服法/方后注 |
| `related_clauses` | array | 否 | 引用该方的条文 ID |
| `related_formulas` | array | 否 | 类方/加减关系 |
| `related_formulas[].relation` | string | 是 | 如“加减方”“类方” |
| `related_formulas[].target` | string | 是 | 目标方剂 ID |
| `related_formulas[].note` | string | 否 | 说明 |
| `safety_notice` | string | 是 | 固定安全提示 |
| `main_symptoms` | array | 否 | 主症术语 ID；缺省自动推导 |
| `pulse` | array | 否 | 脉象术语 ID；缺省自动推导 |
| `pathomechanism` | string | 否 | 病机简述；缺省自动推导，无法推导时留空 |

> 合规：方剂不设“功效/主治/适应症/禁忌症”等现代宣传字段。

### 4.5 药物数据 `herbs.yaml`

```yaml
herbs:
  - id: SHL.SB.H.001
    name: 桂枝
    aliases:
      - 桂
    notes: 可选备注
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 药物 ID |
| `name` | string | 是 | 药名 |
| `aliases` | array | 否 | 别名，用于检索 |
| `notes` | string | 否 | 内部备注 |

- 药物“出现在哪些方中”**不手工维护**，由 `formulas.yaml` 的 `composition` 自动反查。

### 4.6 症状/脉象/病机术语表 `symptom-terms.yaml`

```yaml
terms:
  - id: SHL.SB.SYM.001
    name: 发热
    category: 症状
    aliases:
      - 身热
  - id: SHL.SB.SYM.002
    name: 脉浮
    category: 脉象
  - id: SHL.SB.SYM.003
    name: 恶寒
    category: 症状
  - id: SHL.SB.SYM.004
    name: 营卫不和
    category: 病机
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 术语 ID |
| `name` | string | 是 | 标准名 |
| `category` | enum | 是 | `症状` / `脉象` / `病机` |
| `aliases` | array | 否 | 同义词/近义词，用于检索归一 |

- 条文 `symptom_tags` 和方剂 `main_symptoms` / `pulse` 只能引用此表中的 ID。
- `category` 用于自动推导时分组。

### 4.7 人工复核题 `questions.yaml`

自动生成题不落盘；只有人工复核过、需要固定 ID 的题目才写入此文件。

```yaml
questions:
  - id: SHL.SB.Q.0001
    type: fill_blank
    clause: SHL.SB.TYS.001
    prompt: 太阳之为病，脉浮，头项强痛而＿＿＿。
    options:
      - 恶寒
      - 恶风
      - 发热
      - 汗出
    answer_index: 0
    rationale: 原文“太阳之为病，脉浮，头项强痛而恶寒。”
    status: reviewed
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 题目 ID |
| `type` | enum | 是 | `fill_blank` / `clause_chain` / `formula_syndrome_match` / `formula_composition` |
| `clause` | string | 是 | 题目来源条文 ID |
| `formula` | string | 否 | 方证匹配/方剂组成题关联的方剂 ID |
| `prompt` | string | 是 | 题干 |
| `options` | array | 是 | 选项，至少 4 个 |
| `answer_index` | integer | 是 | 正确选项下标 |
| `rationale` | string | 是 | 解析/原文依据 |
| `status` | enum | 是 | `auto` / `reviewed`；落盘文件只能为 `reviewed` |

## 5. 自动推导规则

### 5.1 方剂对比字段（MVP 先自动推导）

方剂详情页与方证对比表需要“主症、脉象、病机”，MVP 阶段不强制手工录入，按以下规则推导：

1. **主症（main_symptoms）**：收集该方 `related_clauses` 中所有条文的 `symptom_tags`，筛出 `category = 症状`，去重后按出现频次降序。
2. **脉象（pulse）**：同一来源筛出 `category = 脉象`，去重后按出现频次降序。
3. **病机（pathomechanism）**：同一来源筛出 `category = 病机`，若存在则取出现频次最高的术语名；若没有，对比表该列显示“待补充”，不阻断功能。
4. 若方剂数据中手工填写了 `main_symptoms` / `pulse` / `pathomechanism`，则**手工值优先**，不再自动覆盖。
5. 推导结果属于展示层/查询层逻辑，不写回 YAML。

### 5.2 药物反查

- `herb.formulas` 不落盘；由 `formulas.yaml` 的 `composition[].herb` 自动建立“药物 → 方剂”索引。

### 5.3 自动出题 ID

- 未落盘的自动生成题使用**确定性 ID**：`hash(书.版.来源ID.题型.参数)`，保证同一内容每次生成结果一致，错题本才能稳定引用。
- 具体 hash 算法在 `src/domain/quiz/` 实现，并在 `tests/` 覆盖。

## 6. 校验规则（构建期强制）

以下任一不满足，`npm run validate:content` / 构建必须失败，并输出具体文件、字段与修正建议：

1. **ID 唯一**：所有实体 ID 不得重复。
2. **ID 格式**：符合第 3 节格式。
3. **必填字段**：第 4 节标记为“是”的字段不得为空。
4. **条文完整性**：每条条文必须有原文、白话译文、至少 1 条注解。
5. **引用完整性**：
   - 条文 `formulas` 引用的方剂必须存在；
   - 方剂 `composition[].herb` 引用的药物必须存在；
   - 方剂 `related_clauses` 引用的条文必须存在；
   - `related_formulas[].target` 引用的方剂必须存在；
   - 条文 `symptom_tags` 和方剂 `main_symptoms` / `pulse` 引用的术语必须存在于 `symptom-terms.yaml`。
6. **题目合法性**：`answer_index` 在 `options` 下标范围内；`clause` / `formula` 引用存在。
7. **方剂安全提示**：所有方剂必须有 `safety_notice`。
8. **合规词检查**：全量内容不得出现“诊断”“治疗方案”“推荐用药”等禁用词（白名单例外需在 `scripts/validate-content.ts` 中显式登记）。
9. **章节合并无冲突**：同一篇拆分的多个文件合并后，`no` 不得重复、`id` 不得重复。

## 7. 内容文件行数与拆分

1. 内容 YAML 属于数据文件，**不适用手写代码 500 行限制**。
2. 单文件建议不超过 **1000 行**；超过 1000 行时按“篇 + 段”拆分：
   - 文件命名：`<篇代码小写>-<段序号>.yaml`，如 `taiyang-zhong-1.yaml`、`taiyang-zhong-2.yaml`。
   - 拆分文件的 `chapter.code`、`chapter.name`、`chapter.order` 必须相同，`part` 从 1 开始递增。
   - `edition.yaml` 的 `chapters[].files` 按顺序列出全部拆分文件。
3. `formulas.yaml`、`herbs.yaml`、`symptom-terms.yaml`、`questions.yaml` 若超过 1000 行，也按同样原则拆分为 `formulas-1.yaml` 等，并在 `edition.yaml` 或约定目录中登记。

---

## 8. 构建与加载约定

1. `scripts/validate-content.ts`：读取全部 YAML，执行第 6 节校验。
2. `scripts/build-content.ts`：校验通过后生成 `src/data/generated/` 下的 JSON 或 TS 模块，供运行时使用。
3. 运行时**不直接读取 YAML**，只加载构建产物，保证类型安全与体积可控。
4. `src/data/types.ts` 中的 TypeScript 类型必须与本文档字段一一对应；新增字段必须先更新本文档。
