# 测试计划

> 版本：v0.1
> 配套：`docs/核心模块设计.md`、`docs/数据规范.md`
> 用途：明确 MVP 各模块需要覆盖的测试范围，供开发时编写测试用例。

---

## 1. 测试分层

| 层级 | 工具 | 覆盖内容 |
|---|---|---|
| 单元测试 | Vitest | domain 纯逻辑、store 工具函数 |
| 组件测试 | Vitest + @vue/test-utils | 关键 UI 组件交互 |
| 内容校验测试 | Vitest / 脚本 | 数据规范校验规则 |
| 迁移测试 | Vitest | Dexie 版本迁移、备份导入导出 |
| E2E（后期） | Playwright（可选） | 核心用户流程、PWA 离线 |

---

## 2. 记忆模块（FSRS）测试

### 2.1 必须覆盖

- [ ] 新卡创建后状态为 New；
- [ ] 新学“学会了”后创建首次复习计划；
- [ ] 自评映射：忘了 → Again、模糊 → Hard、记得 → Good；
- [ ] 复习后卡片 `due`、`interval`、`stability` 正确更新；
- [ ] 到期卡片查询：`due <= 今天` 才返回；
- [ ] 今日队列：到期复习 + 新学合并；
- [ ] 队列超过 20 条时，优先复习、新学顺延；
- [ ] 两个 active 计划时，新学按各计划分别取并合并；
- [ ] 同一条文不会因多个计划重复“首次学习”；
- [ ] 断签不影响内容进度，只影响 streak。

---

## 3. 出题模块测试

### 3.1 必须覆盖

- [ ] 四种题型都能从内容数据生成；
- [ ] 正确答案有原文依据；
- [ ] 选项不重复、数量正确；
- [ ] 自动生成题 ID 稳定（同一参数多次生成一致）；
- [ ] 人工复核题优先于自动生成题；
- [ ] 错题能按 `questionId` 稳定记录；
- [ ] 数据不足时能优雅降级（如找不到足够干扰项）。

---

## 4. 搜索模块测试

### 4.1 必须覆盖

- [ ] 中文二字切词符合预期；
- [ ] 多关键词空格分隔默认 AND；
- [ ] 条文、方剂、药物分组正确；
- [ ] 命中高亮位置正确；
- [ ] 空查询返回空结果；
- [ ] 无结果时展示空状态；
- [ ] 搜索不返回诊断/推荐内容。

---

## 5. 内容校验测试

### 5.1 必须覆盖

- [ ] ID 重复能报错；
- [ ] ID 格式错误能报错；
- [ ] 缺译文、缺注解能报错；
- [ ] 引用不存在的方剂/药物/术语能报错；
- [ ] 题目 `answer_index` 越界能报错；
- [ ] 禁用词能报错；
- [ ] 拆分文件合并后条文号重复能报错；
- [ ] 错误信息包含文件、字段、修正建议。

---

## 6. 存储/迁移测试

### 6.1 必须覆盖

- [ ] Dexie 各表能正常读写；
- [ ] 版本升级迁移不丢数据；
- [ ] 备份导出包含全部用户数据；
- [ ] 导入前校验 `schemaVersion`；
- [ ] 导入前自动备份当前数据；
- [ ] 导入失败时原数据不被破坏。

---

## 7. 组件/页面测试（关键项）

- [ ] 背诵卡翻面与三自评交互；
- [ ] 每日任务进度与打卡状态；
- [ ] 搜索页输入、分组、高亮、空状态；
- [ ] 方证对比表自动推导字段展示；
- [ ] 统计页各指标计算展示；
- [ ] 首次进入协议同意流程。

---

## 8. 测试命令

```bash
npm run test          # 运行全部测试
npm run test:unit     # 仅单元/组件测试（如有拆分）
npm run validate:content  # 内容校验
```

---

## 9. 提交要求

- 每个功能提交前必须运行 `npm run test` 和 `npm run validate:content`；
- 新增核心逻辑必须补对应测试；
- 测试失败不允许合入。
