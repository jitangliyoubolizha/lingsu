# 测试计划

> 版本：v0.3
> 配套：`docs/核心模块设计.md`、`docs/数据规范.md`
> 用途：明确 MVP 各模块需要覆盖的测试范围，供开发时编写测试用例。

---

## 1. 测试分层

| 层级 | 工具 | 覆盖内容 |
|---|---|---|
| 单元测试 | Vitest | domain 纯逻辑、store 工具函数 |
| 组件测试 | Vitest + @vue/test-utils | 关键 UI 组件交互 |
| 内容校验测试 | Vitest / 脚本 | 数据规范校验规则 |
| 迁移测试 | Vitest | Dexie 版本迁移、备份导入导出 |
| E2E（后期） | Playwright（可选） | 核心用户流程、PWA 离线 |

---

## 2. 记忆模块（FSRS）测试

### 2.1 必须覆盖

- [x] 新卡创建后状态为 New；
- [ ] 新学“学会了”后创建首次复习计划；
- [ ] 自评映射：忘了 → Again、模糊 → Hard、记得 → Good；
- [ ] 复习后卡片 `due`、`interval`、`stability` 正确更新；
- [x] 到期卡片查询：`due <= 今天` 才返回；
- [x] 今日队列：到期复习 + 新学合并；
- [x] 队列超过 20 条时，优先复习、新学顺延；
- [x] 两个 active 计划时，新学按各计划分别取并合并；
- [x] 同一条文不会因多个计划重复“首次学习”；
- [x] 断签不影响内容进度，只影响 streak。

### 2.5 错题排期（轻 Leitner）测试

- [x] 答错后次日到期、连续答对清零；
- [x] 答对一次 3 天后复测、未掌握；
- [x] 连续答对两次标记已掌握；
- [x] 到期队列只取未解决且到期错题，按到期时间排序、每次最多 10 道；
- [x] v1→v2 迁移为旧错题补齐 `dueAt` 与 `correctStreak`。

## 8. 测试命令

```bash
npm run test          # 运行全部测试
npm run test:unit     # 仅单元/组件测试（如有拆分）
npm run validate:content  # 内容校验
```

---

## 9. 提交要求

- 每个功能提交前必须运行 `npm run test` 和 `npm run validate:content`；
- 新增核心逻辑必须补对应测试；
- 测试失败不允许合入。
