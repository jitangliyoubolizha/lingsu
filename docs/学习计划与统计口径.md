# 学习计划与统计口径

> 版本：v0.1
> 配套：`docs/PRD.md` §5.6 / §5.8、`docs/数据规范.md`
> 用途：把“学习计划、每日任务、FSRS、统计指标”的定义固定下来，供开发直接实现。

---

## 1. 概念关系

| 概念 | 职责 |
|---|---|
| 学习计划 | 决定“每天新学哪些条文”的顺序与进度 |
| FSRS | 决定“学过的条文什么时候复习” |
| 每日任务 | 把“当日新学 + 到期复习”合成一个可完成的学习队列 |
| 统计 | 从学习行为记录中计算打卡、进度、正确率、保持率等指标 |

一句话：**学习计划负责发新卡，FSRS 负责安排复习，每日任务负责执行，统计负责展示结果。**

---

## 2. 学习计划模型（MVP）

### 2.1 定义

学习计划是“新卡发放器”，只控制新学内容的来源和节奏，不干预复习调度。

### 2.2 数据模型

```ts
interface StudyPlan {
  id: string
  name: string               // 如“太阳病上篇 30 天计划”
  scope: {
    book: string             // 书代码，如 SHL
    edition: string          // 版本代码，如 SB
    chapters: string[]       // 篇章代码列表，如 ['TYS']
  }
  dailyNew: 3 | 5 | 10       // 每日新学数量
  startDate: string          // 开始日期 YYYY-MM-DD
  status: 'active' | 'paused' | 'completed'
}
```

每个条文的“是否已学”单独记录：

```ts
interface ClauseStudyState {
  clauseId: string           // SHL.SB.TYS.001
  firstLearnedAt?: string    // 首次学习日期，存在即视为“已学”
}
```

### 2.3 行为规则

1. 每日新学：从“属于计划范围、且没有 `firstLearnedAt` 的条文”中，按条文号升序取 `dailyNew` 条。
2. 如果当天到期复习过多，**新学顺延**，不强制塞满队列。
3. MVP 最多支持 **两个 `active` 计划**；每个计划独立按自己的 `dailyNew` 取新学。
4. 新增/切换计划：已学记录保留；新计划只从未学条文中继续取；同一条文不会因多个计划被重复“首次学习”。
5. “重新开始计划”：只重置该计划的新学进度，**不删除已学卡片和复习记录**；如需彻底清除，使用“清除本机数据”。
6. 若两个计划当天都有新学，合并进今日队列；超过 20 条时优先复习、新学顺延。
7. 预计完成天数：

```
预计剩余天数 = ceil(剩余未学条文数 / dailyNew)
```

## 3. 每日任务模型

### 3.1 队列组成

```
今日队列 = 到期背诵复习卡片 + 到期错题巩固 + 当日新学条文
```

- 到期复习：FSRS 中 `due <= 今天` 的卡片；
- 到期错题巩固：轻 Leitner 中 `dueAt <= 今天` 且未掌握的错题，每次最多 10 道（规则见 `docs/核心模块设计.md` §7.3）；
- 当日新学：按学习计划规则取出的新条文；存在两个 active 计划时，合并两个计划的新学；
- 单日队列上限确定为 **20 条**；
- 若到期复习超过上限，按「背诵复习 → 错题巩固 → 新学」顺序保留，其余顺延。

### 3.2 新学卡片流程

1. 展示原文；
2. 用户点击“学会了”；
3. 系统为该条文创建 FSRS 卡片并安排首次复习。

> 新学卡片不做“忘了/模糊/记得”自评，避免用户还没学就自评失败。

### 3.3 复习卡片流程

1. 显示提示（条文号、首句片段或方证提示）；
2. 用户先在脑中回忆；
3. 点击翻面查看原文；
4. 自评：记得 / 模糊 / 忘了；
5. 系统按 FSRS 安排下次复习。

### 3.4 FSRS 自评映射

| 用户自评 | 含义 | FSRS rating |
|---|---|---|
| 忘了 | 完全没回忆起来 | Again（1） |
| 模糊 | 想起来但不确定 | Hard（2） |
| 记得 | 顺利回忆出来 | Good（3） |

- MVP 不提供 Easy（4），后续可增加“轻松”按钮；
- “模糊”映射 Hard，不映射 Good；
- “忘了”必须映射 Again。

### 3.5 错题巩固

- 轻 Leitner：答错次日到期；答对 3 天后复测；连续答对 2 次移入“已掌握”；
- 每日队列中错题巩固位于背诵复习之后、新学之前，每次最多 10 道；
- 错题巩固计入今日任务完成数（`dailyLogs` 的 required/completed）。

### 3.6 打卡与连续天数

- 完成“全部到期背诵复习 + 到期错题巩固 + 当日新学”即视为完成今日任务；
- 用户额外多做的复习不计入“必须项”；
- 连续打卡天数按“完成每日任务的自然日”计算。

## 4. 统计口径

### 4.1 条文学习状态

| 状态 | 判定标准 |
|---|---|
| 未学 | 没有 `firstLearnedAt` |
| 已学 | 有 `firstLearnedAt` |
| 学习中 | 已学，且 FSRS 状态为 Learning / Relearning，或当前复习间隔 < 21 天 |
| 已掌握 | 已学，且 FSRS 状态为 Review，并且当前复习间隔 ≥ 21 天 |

> 21 天为 MVP 阈值，后续可根据真实数据调整。

### 4.2 指标定义

| 指标 | 定义 |
|---|---|
| 已学条文数 | 有 `firstLearnedAt` 的条文数量 |
| 学习中数量 | 满足“学习中”判定标准的条文数量 |
| 已掌握数量 | 满足“已掌握”判定标准的条文数量 |
| 篇章进度 | `该篇已学条文数 ÷ 该篇总条文数` |
| 待复习数量 | FSRS 中 `due <= 今天` 的卡片数 |
| 今日任务完成情况 | `今日已完成卡片数 ÷ 今日应完成卡片数` |
| 累计学习天数 | 有过学习行为（完成过任务或复习过卡片）的不同自然日数量 |
| 连续打卡天数 | 从“今天或昨天”往前数，连续完成每日任务的自然日数量 |
| 刷题正确率 | `正确答题数 ÷ 总答题数` |
| 各题型正确率 | `该题型正确答题数 ÷ 该题型总答题数` |
| 记忆保持率 | `(记得次数 + 模糊次数) ÷ 复习总次数` |
| 严格记忆保持率 | `记得次数 ÷ 复习总次数`（可选展示） |

### 4.3 打卡与日期规则

1. 所有日期按**用户本地自然日**计算，不使用 UTC。
2. 连续打卡：
   - 今天已完成 → 从今天开始往前数；
   - 今天未完成 → 从昨天开始往前数，避免用户一打开 App 就断签。
3. 断签只影响连续打卡天数，不影响已学内容、FSRS 卡片和累计学习天数。

### 4.4 记忆保持率趋势

- 按周或按月聚合；
- 分子分母分别累计该周期内的“记得 + 模糊”次数和复习总次数；
- 例如本月保持率 = 本月“记得 + 模糊”次数 ÷ 本月复习总次数。

## 5. 需要落地的数据字段

| 数据 | 字段/表 |
|---|---|
| 学习计划 | `study_plans`：id、name、scope、dailyNew、startDate、status |
| 条文学习状态 | `clause_states`：clauseId、firstLearnedAt |
| FSRS 卡片 | `cards`：clauseId、状态、间隔、到期日、历史记录 |
| 每日完成记录 | `daily_logs`：date、requiredCount、completedCount |
| 刷题记录 | `quiz_logs`：questionId、correct、type、timestamp |
| 自评记录 | `review_logs`：cardId、rating、timestamp |

> 具体 IndexedDB 表结构在开发时由 `src/store/` 实现，字段以本文档为准。
