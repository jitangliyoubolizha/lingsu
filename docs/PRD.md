## 1. 产品概述

### 1.1 背景与问题

中医学生和爱好者在学习《伤寒论》时普遍遇到：

1. 条文记不住、背了容易忘，缺少科学的复习安排；
2. 方证容易混淆，缺少“方—证—条文—药物”之间的对照与串联；
3. 想在碎片时间刷题巩固，但没有轻量、趁手的工具；
4. 想快速检索条文和方剂，缺少移动端友好的检索工具。

### 1.2 产品定位

**《伤寒论》经典文献学习与记忆工具**：

- 以条文背诵与科学复习为核心；
- 以方证对照、方药串联为特色；
- 以原文检索和刷题巩固为辅助；
- **仅用于中医经典学习与文献检索，不提供诊疗建议、不开展互联网诊疗、不提供用药推荐。**

### 1.3 目标用户

| 用户 | 主要诉求 |
|---|---|
| 中医学生（主要） | 背条文、准备考试、理清方证关系 |
| 中医爱好者（主要） | 入门学习、理解条文、轻量坚持打卡 |
| 临床医师（次要） | 快速检索条文与方剂信息，辅助温习 |

### 1.4 产品原则

1. **学习优先**：一切功能围绕“记住、理解、会查”展开。
2. **不涉诊疗**：只做文献学习，不给诊断或用药结论。
3. **内容可靠**：以宋本为底本，白话译文自行编写，名家注解选用公版文献。
4. **轻量易坚持**：每日 5 分钟左右即可完成核心任务。
5. **低成本可扩展**：第一版无服务器；未来可加书、加账号，程序结构预留扩展能力。

## 2. 目标与成功标准

### 2.1 第一版（MVP）成功标准

1. 用户能按遗忘曲线完成每日背诵任务并打卡，持续记住条文；
2. 用户能查询任意方剂，看到组成、剂量、相关条文、类方与加减关系；
3. 用户能用关键词快速检索到相关条文；
4. 用户能收藏条文，错题自动进入错题本并按计划复习；
5. 学习进度保存在本机，可导出/导入备份，不因换设备或清缓存而完全丢失。

### 2.2 本期不做（Non-goals）

- 不做 AI 问答、AI 白话解释；
- 不做症状辨证推理、诊断建议、用药推荐；
- 不做账号系统、云端同步、社区、评论；
- 第一版不做微信小程序、App 壳；
- 第一版不做方药关系节点图（关系图放第二版）；
- 第一版内容只覆盖《伤寒论》，暂不包含《金匮要略》等其他书籍。

## 3. 用户与核心场景

### 3.1 典型场景

1. **碎片背诵**：学生每天通勤或睡前打开 App，完成“今日任务”（新学 + 复习），看到连续打卡天数增加。
2. **考前刷题**：按篇章刷选择题（挖空、接龙、方证匹配、方剂组成），错题自动进入错题本。
3. **查方对照**：输入“桂枝汤”，看到组成剂量、相关条文、类方加减；再打开“桂枝汤 vs 麻黄汤”对比表。
4. **按症状找条文**：临床医师输入“发热 汗出 恶风”，快速找到相关条文原文，用于温习。
5. **复习统计**：查看学习日历、记忆保持率、篇章进度，判断下一步复习重点。

## 4. 内容范围与来源

### 4.1 底本与文字

- 底本：宋本《伤寒论》（明·赵开美复刻宋本系统），按中医院校教材通行的篇目顺序编排。
- 文字：简体中文。
- 条文编号：采用“篇名 + 第 N 条”，例如“辨太阳病脉证并治上·第 1 条”。
- 篇目：辨太阳病（上、中、下）、辨阳明病、辨少阳病、辨太阴病、辨少阴病、辨厥阴病、辨霍乱病、辨阴阳易差后劳复病。

### 4.2 内容建设节奏

| 阶段 | 内容范围 |
|---|---|
| MVP（第一版） | 《伤寒论》太阳病三篇全部条文（约 178 条，具体以校勘为准），及这些条文涉及的方剂、药物、注解、题目 |
| 第一版完整版 | 补齐《伤寒论》全部 398 条、113 方（含 1 首有名无方者，数据中特别标注） |
| 后续 | 视使用情况增加《金匮要略》等书籍；加书时只新增“书”一层数据，不影响原有结构 |

### 4.3 每条条文包含的板块

MVP 每条条文至少包含：

| 板块 | 说明 |
|---|---|
| 原文 | 简体，忠实底本 |
| 条文编号与位置 | 篇名 + 第 N 条 |
| 白话译文 | 每条 1 段，由 AI 按通行教材理解编写（初稿）；专业人工校对后置，上线后依用户反馈纠错 |
| 名家注解 | 选自公版注家（成无己、柯琴、尤在泾等）；普通条文 1 家，重要条文 2–3 家，注明出处 |
| 相关方剂 | 条文涉及的方剂链接 |
| 主症标签 | 结构化症状关键词（如：发热、汗出、恶风、脉缓），用于方证匹配与检索 |
| 学习标签 | 用于卡片提示的提示语/关键词 |

### 4.4 方剂字段

| 字段 | 说明 |
|---|---|
| 方名 | 如桂枝汤、麻黄汤 |
| 类方归属 | 桂枝汤类、麻黄汤类、柴胡汤类等（按教材通行分类） |
| 组成 | 药物及原书剂量 |
| 原书剂量 | 两、升、枚等原文单位 |
| 古今剂量参考 | 可展开区域展示；换算默认按中医药大学研究数据计算（具体出处与表述上线前标注），同时注明古今剂量存在学术争议；**标注“学术探讨，非用药指导”** |
| 煎服法 | 原文煎服法、方后注 |
| 相关条文 | 引用该方的条文 |
| 类方/加减关系 | 如桂枝汤 → 桂枝加葛根汤、桂枝加附子汤 |
| 所含药物 | 反向查看每味药出现在哪些方中 |
| 安全提示 | 固定风险提示，不可关闭 |
| 主症 / 脉象 / 病机 | 供方证对比表使用；MVP 阶段可缺省，由系统从相关条文自动推导（见 `docs/数据规范.md` §5） |

**合规决定：不设置现代“功效/主治”宣传字段，方剂主治一律通过相关条文和古籍注解呈现。**

### 4.5 数据模型与命名规范

为满足“未来加书、条文不混淆”的要求，所有内容采用四层结构：

```
书 → 版本 → 篇 → 条文号
```

- 内部唯一标识示例：`SHL.SB.TYS.001`（伤寒论 / 宋本 / 辨太阳病脉证并治上 / 第 1 条）
- 页面显示：`辨太阳病脉证并治上·第 1 条`
- 未来新增书籍只需增加新的书代码，如《金匮要略》用独立代码，条文、方剂、药物均带所属书信息，互相不冲突。
- 字段级数据规范见 `docs/数据规范.md`（目录结构、YAML 字段、ID、校验、自动推导规则）。

## 5. 功能需求

> 优先级：P0 = MVP 必须；P1 = 完整版必须；P2 = 后续版本。

### 5.1 首次进入与合规确认（P0）

- 首次打开显示产品定位说明与免责声明；
- 用户须同意《用户协议与免责声明》后才能使用学习功能；
- 协议内容要点：本工具仅供学习研究；不构成医疗建议；处方须由执业医师开具；原书剂量为古代度量衡，不可自行照方抓药；身体不适应及时就医。

### 5.2 条文浏览与分类（P0）

- 三种浏览入口：
  1. 按篇：六经篇目 → 条文列表；
  2. 按方：类方分组 → 方剂 → 相关条文；
  3. 按条文号：直接跳转某条。
- 条文列表支持筛选：全部 / 未学 / 学习中 / 已掌握 / 已收藏。
- 条文列表显示：条文号、原文首句、是否已学、是否已收藏。

### 5.3 条文详情页（P0）

- 原文为主视觉；
- 可展开/收起：白话译文、名家注解（注明出处）；
- 展示：相关方剂、主症标签、上一条/下一条；
- 操作：加入学习、收藏、加入/移出错题（朗读暂不纳入第一版）；
- 顶栏提供「纠错」入口，跳转反馈页并自动带当前条文位置；
- 固定免责声明入口。

### 5.4 全文/关键词搜索（P0）

- 搜索范围：条文原文、白话译文、名家注解、方名、药物名；
- 结果分组：条文 / 方剂 / 药物；
- 支持多关键词空格分隔（“发热 汗出 恶风”）；
- 命中关键词高亮显示；
- 症状反查即使用本搜索：**只返回包含关键词的条文原文，不给诊断结论、不推荐方剂**；
- 搜索完全在本地完成，无网络请求。

### 5.5 方证对照与方药串联（P0）

- 方剂详情页：组成剂量、煎服法、相关条文、类方与加减关系、所含药物、安全提示；
- 药物详情页：该药出现在哪些方中；
- 类方页：桂枝汤类、麻黄汤类等分组浏览；
- 方证对比表：任选 2–4 首方横向对比（组成、主症、脉象、病机、相关条文）；MVP 阶段“主症/脉象/病机”先由相关条文自动推导，规则见 `docs/数据规范.md` §5；
- 关系节点图：P2（第二版）。

### 5.6 条文背诵与复习（P0，核心功能）

#### 5.6.1 每日轻量任务

- **每日任务只做“条文背诵/复习卡片”，不包含选择题**；选择题统一放到 §5.7 刷题模块。
- 每日队列组成：
  - 到期复习：FSRS 中 `due <= 今天` 的卡片；
  - 当日新学：按当前学习计划从未学条文中按顺序取 N 条，默认 3，可调 5/10；
  - 单日队列上限确定为 **20 条**；若到期复习过多，**优先复习，新学顺延**。
- 新学卡片流程：
  1. 先展示原文；
  2. 用户点“学会了”后进入复习节奏；
  3. 系统按 FSRS 安排首次复习时间。
- 复习卡片流程：
  1. 显示提示（条文号、首句片段或方证提示）；
  2. 用户先在脑中回忆；
  3. 点击翻面查看原文；
  4. 自评：记得 / 模糊 / 忘了；
  5. 系统按 FSRS 安排下次复习时间。
- 自评映射（MVP 固定）：
  - 忘了 → Again（1）
  - 模糊 → Hard（2）
  - 记得 → Good（3）
  - MVP 不提供 Easy（4），后续可增加“轻松”按钮。
- 完成“全部到期复习 + 当日新学”即打卡，显示连续打卡天数（streak）。

#### 5.6.2 遗忘曲线算法

- 使用 FSRS 间隔重复算法，在浏览器本地计算；
- 根据自评结果动态调整复习间隔；
- 断签不惩罚内容进度，只影响连续天数统计。

#### 5.6.3 学习计划

- 学习计划**只决定“每天新学哪些条文”**，不负责复习调度；复习由 FSRS 负责。
- 用户可选择篇章开启计划，如“太阳病上篇 30 天计划”；
- 用户可为每个计划设置每日新学数量（3 / 5 / 10）；
- 系统按条文顺序每天从各计划从未学条文中取 N 条作为当日新学；
- 首页显示当前计划名称、已学 X / 总 Y、预计剩余天数；
- MVP 最多支持 **两个进行中的计划**，可切换、暂停或重新开始；
- 若两个计划同时有新学，合并进今日队列；超过 20 条时优先复习、新学顺延；
- 详细数据模型与统计口径见 `docs/学习计划与统计口径.md`。

#### 5.6.4 题型（刷题模块，全部为选择题，不打字）

- 以下题型属于 §5.7 刷题模块，**不属于每日任务**。

| 题型 | 说明 |
|---|---|
| 挖空选择 | 条文挖掉一个关键词，四选一补全 |
| 条文接龙 | 给上句选下句 / 给下句选上句 |
| 方证匹配 | 给症状群选对应方（如“发热、汗出、恶风、脉缓”选桂枝汤） |
| 方剂组成 | 判断某药是否属于某方 / 选出某方所含药物 |

- 答错立即显示正确答案与原文依据；
- 错题自动进入错题本，可在刷题/错题本中重做；
- 题目由系统根据条文和方药数据自动生成，重要条文题目人工复核。

### 5.7 测验刷题（P0）

- 刷题模式：按篇、按题型、按错题本、随机综合；
- 每次进入刷题页时对题目选项做随机洗牌并重算答案位置，避免正确选项固定在同一字母位置；
- 每次练习建议 5–10 题，完成后显示正确率；
- 支持中断后继续。

### 5.8 学习数据统计（P0）

- 所有统计指标的具体口径以 `docs/学习计划与统计口径.md` 为准；
- 学习日历（打卡热力图）；
- 连续打卡天数、累计学习天数；
- 已学条文数、学习中/已掌握数量、篇章进度；
- 待复习数量、今日任务完成情况；
- 刷题正确率、各题型正确率；
- 记忆保持率趋势。

### 5.9 收藏与错题本（P0）

- 收藏：可收藏条文和方剂，支持列表查看与取消；
- 错题本：按题存储，显示错题来源条文，支持重做、移出错题本。

### 5.10 数据备份（P0）

- 导出：将学习进度、卡片状态、收藏、错题、设置导出为 JSON 文件；
- 导入：从 JSON 文件恢复；
- 第一版导入为“确认后覆盖本机数据”，多端合并放后续版本。

### 5.11 设置（P0）

- 每个学习计划的每日新学数量（3 / 5 / 10）；
- 字号大小（小 / 中 / 大）；
- 清除本机数据；
- 查看免责声明、内容来源说明、版本信息；
- 意见反馈入口；
- 朗读设置项暂不提供（第一版不纳入）。

### 5.12 朗读（已确认：第一版不纳入，后续版本可选）

- 使用浏览器系统语音（Web Speech API）朗读条文；
- 零成本，但不同手机系统音色不一致；
- 第一版不提供朗读入口与设置项；
- 后续版本如纳入，默认关闭，可在设置中开启。

### 5.13 意见反馈（P0）

- 入口：全局底部常驻提示条「内容纠错」、我的页「意见反馈」、条文详情页顶栏与学习卡片页顶栏（自动预填当前条文位置）；
- 站内表单字段：反馈类型（条文/方剂/功能/其他）、位置或条号（选填）、问题描述（必填，≤500 字）、联系方式（选填）；
- 提交方式：生成预填 `mailto:` 邮件发送至 `l2752255876@gmail.com`，无需注册登录；
- 用途：作为内容纠错与功能反馈的统一渠道（专业人工校对后置）。

## 6. 内容质量与合规要求

### 6.1 内容质量

- 所有原文在发布前完成录入与结构校验，并记录底本来源；专业校勘后置，上线后依用户反馈持续修订并记录依据；
- 白话译文必须忠实原文、符合教材通行理解，不擅自发挥；
- 名家注解必须注明书名、作者、篇目；
- 结构化数据（方、药、条文关系）在构建时自动校验：无孤儿条文、无空译文、方剂药物关系可追溯；
- 方剂剂量照录原文，换算内容显著标注学术争议。

### 6.2 医疗合规红线

1. 产品内任何位置不得出现“诊断”“治疗方案”“推荐用药”等表述；
2. 症状检索只呈现条文原文，不生成任何判断或建议；
3. 方剂页固定安全提示，不得隐藏或折叠；
4. 不设置现代功效主治、适应症、禁忌症等宣传性字段；
5. 全站免责声明 + 用户协议；
6. 若未来公开运营，需另行完成备案与专业法律合规审查（本 PRD 不构成法律意见）。

### 6.3 版权

- 古籍原文、古代注家著作：公版内容，可公开使用；
- 白话译文：项目自行编写；
- 不使用现代教材的受版权保护的翻译、讲解、图表；
- 公开发布前逐项核对文本来源与授权。

## 7. 技术方案（概要）

### 7.1 技术栈（默认方案）

| 模块 | 方案 |
|---|---|
| 语言 | TypeScript |
| 框架 | Vue 3 + Vite（默认；如产品方指定其他框架可调整） |
| 样式 | Tailwind CSS + 自定义设计变量（视觉由产品方补充） |
| 路由 | Vue Router，hash 模式（适配免费静态托管） |
| 本地存储 | IndexedDB（Dexie 封装） |
| 遗忘曲线 | ts-fsrs（浏览器本地运行） |
| 搜索 | MiniSearch + 中文切词，本地索引 |
| 统计图表 | ECharts |
| PWA | vite-plugin-pwa，可安装、可离线 |
| 朗读 | Web Speech API（可选） |
| 测试 | Vitest（记忆算法、出题逻辑、内容校验） |
| 内容格式 | 版本化 YAML/JSON + 构建时校验 |
| 部署 | 免费静态托管（Cloudflare Pages / Vercel / GitHub Pages，上线时定） |

### 7.2 结构分层

```
content/     内容源文件：书 → 版本 → 篇 → 条文、方、药、注、题
src/domain/  核心逻辑：记忆算法、出题、方药关系、检索（不依赖界面框架）
src/data/    数据加载与校验
src/store/   学习状态、设置、统计
src/ui/      页面与组件（手机优先）
```

- 未来上微信小程序时，`content/` 与 `src/domain/` 基本可复用；
- 未来加账号同步时，仅替换本地存储为云端存储适配器；
- 未来加书时，仅新增内容文件。

## 11. 视觉设计（产品方已确认）

> 完整版见 `design/设计规范.md`（设计令牌、组件规范、页面规范、合规视觉红线、实现约定）。
> 原型稿见 `design/preview/`（HTML 预览）与 `design/灵素-UI原型.pen`（Pencil 源文件）。

### 11.1 风格

- **新中式（Modern Chinese Classic）**：不追求极简，具备古籍厚重感与沉浸感。
- 气质关键词：宣纸、水墨、朱砂、靛青、界行、折扇、印章。

### 11.2 色彩令牌（摘要）

| 令牌 | 值 | 用途 |
|---|---|---|
| `paper` | `#F6F1E7` | 页面背景（宣纸暖米黄，护眼不刺眼） |
| `ink` | `#2B2720` | 正文、图标（暖褐水墨黑，非纯黑） |
| `cinnabar` | `#8B0000` | 主按钮、强调（朱砂红） |
| `indigo` | `#35506B` | 交互链接（靛青） |
| `gold` | `#C9A227` | 收藏星标、「模糊」自评 |
| `green` | `#3E7C4F` | 正确反馈、「记得」自评 |
| `red` | `#A33A3A` | 警告文字、「忘了」自评 |

（完整令牌表含浅色底、纸边描边、热力图梯度等，见 `design/设计规范.md` §2）

### 11.3 字体

- 古籍原文与各级大标题：衬线 `Noto Serif SC`（宋体类）；
- 现代 UI 元素（按钮、标签、统计、导航）：无衬线 `Noto Sans SC`；
- 原文 24–28px、行高 1.6–1.8；正文不小于 12px；设置页提供小/中/大三档字号。

### 11.4 图标

- 通用交互一律线性图标（lucide）、水墨黑：放大镜=搜索、星形=收藏、房子=首页、文档=刷题、人像=我的；
- 业务特色定制图形：印章「灵」（App 标识）、葫芦（连续打卡）、折扇纹（分隔线）、找方=九宫格（百子柜意象）。

### 11.5 组件与页面

- 核心组件：StatusBar、Tag 胶囊、主/次按钮、搜索栏、卡片、篇章进度条、折叠面板（折扇纹分隔）、吸底导航、选项卡、合规警告横幅、热力图、挖空样式；
- 原型已覆盖 13 屏：首页学习看板 / 背诵卡正面 / 背诵卡背面（三自评态）/ 条文详情 / 方剂详情 / 测验答题 / 错题反馈 / 搜索 / 统计 / 方证对比 / 协议页 / 条文列表 / 我的；
- 方剂列表页、药物详情页尚未出稿，按 `design/设计规范.md` §5 与 `design/关键页面设计补充.md` 实现，风格与已出稿屏保持一致。

### 11.6 合规视觉红线

1. 条文详情页吸底不可关闭横幅：「仅供学习研究，不构成医疗建议，请勿自行用药」；
2. 方剂剂量换算处红色粗体警告：「学术探讨，非用药指导」；
3. 搜索/症状检索页固定提示：仅供学习研究，不构成医疗建议；
4. 全站不出现「诊断」「治疗方案」「推荐用药」等表述。

### 11.7 实现约定（摘要）

- Tailwind CSS v4 + `:root` CSS 变量承载设计令牌（映射见 `design/设计规范.md` §2.1）；
- 字体：开发阶段可临时使用 Google Fonts `<link>`；PWA 离线验收前必须改为自托管 woff2（见 `design/视觉资源准备方案.md`），并定义工具类；
- `fill_container` → `flex-1`；吸底元素 `fixed` + 底部安全区；
- lucide 注意新版命名：`house`、`triangle-alert`；定制 SVG 从 `design/preview/` 中提取 path 原样复用。
