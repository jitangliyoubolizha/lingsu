# 核心模块设计

> 版本：v0.1
> 配套：`docs/PRD.md`、`docs/数据规范.md`、`docs/学习计划与统计口径.md`
> 说明：本文档定义核心模块的接口、数据表、算法与备份格式，供开发直接实现。

---

## 1. 模块总览

| 模块 | 位置 | 职责 |
|---|---|---|
| 记忆调度 | `src/domain/memory/` | FSRS 卡片、每日队列、学习计划取新卡 |
| 出题 | `src/domain/quiz/` | 自动生成题、确定性 ID、人工复核题覆盖 |
| 检索 | `src/domain/search/` | MiniSearch 索引、中文分词、查询与高亮 |
| 方药关系 | `src/domain/formula/` | 方剂对比字段自动推导、药物反查 |
| 持久化 | `src/store/` | Dexie 表、设置、备份导入导出 |
| 内容加载 | `src/data/` | 读取构建产物、提供类型化数据 |

## 2. IndexedDB 表结构（Dexie）

### 2.1 数据库版本

MVP 使用 Dexie，数据库名 `lingsu`，初始版本 `1`。

### 2.2 表定义

```ts
db.version(1).stores({
  settings:            'key',
  studyPlans:          'id, status',
  clauseStates:        'clauseId, firstLearnedAt',
  cards:               'id, clauseId, due, state',
  reviewLogs:          '++id, cardId, reviewedAt',
  dailyLogs:           'date, requiredCount, completedCount',
  quizLogs:            '++id, questionId, type, answeredAt',
  favorites:           'id, type, targetId',
  wrongQuestions:      'questionId, lastWrongAt, wrongCount',
})
```

### 2.3 表字段说明

| 表 | 字段 | 说明 |
|---|---|---|
| `settings` | key, value | 每日新学数、字号、是否同意协议、朗读开关等 |
| `studyPlans` | id, name, scope, dailyNew, startDate, status | 当前学习计划 |
| `clauseStates` | clauseId, firstLearnedAt | 条文是否已学 |
| `cards` | id, clauseId, due, state, interval, stability, difficulty | FSRS 卡片；state 为 New/Learning/Relearning/Review |
| `reviewLogs` | id, cardId, rating, reviewedAt | 每次自评记录，用于统计 |
| `dailyLogs` | date, requiredCount, completedCount | 每日任务完成情况 |
| `quizLogs` | id, questionId, type, correct, answeredAt | 刷题记录 |
| `favorites` | id, type, targetId, createdAt | 收藏条文/方剂 |
| `wrongQuestions` | questionId, lastWrongAt, wrongCount, resolved | 错题本 |

### 2.4 迁移策略

- 每次结构变更，`db.version(n).stores(...)` 升版本；
- `upgrade` 中只做字段迁移，不丢用户数据；
- 备份导入时若 `schemaVersion` 低于当前版本，先执行迁移再写入。

## 3. FSRS 模块接口

### 3.1 核心函数

```ts
// 创建新卡
function createCard(clauseId: string): Card

// 复习自评
function reviewCard(
  card: Card,
  rating: 1 | 2 | 3,       // 1=Again 2=Hard 3=Good
  now: Date
): { card: Card; log: ReviewLog }

// 获取到期复习
function getDueCards(now: Date): Card[]

// 按学习计划取新条文
function getNewClauses(
  plan: StudyPlan,
  count: number,
  learnedClauseIds: Set<string>
): Clause[]

// 生成今日队列
function getTodayQueue(now: Date): {
  dueCards: Card[]
  newClauses: Clause[]
}
```

### 3.2 自评映射

| 自评 | rating | 说明 |
|---|---|---|
| 忘了 | 1（Again） | 进入重学 |
| 模糊 | 2（Hard） | 间隔适当缩短 |
| 记得 | 3（Good） | 正常复习成功 |

MVP 不传 `4（Easy）`。

### 3.3 规则

1. 所有函数为纯函数，不直接改 IndexedDB；
2. `reviewCard` 返回新卡片和日志，由调用方统一写库；
3. 今日队列 = `due <= 今天` 的卡片 + 按计划取的新条文；
4. 到期复习过多时，新学顺延，不强制补满。

## 4. 出题规则

### 4.1 题型

| 题型 | 生成方式 |
|---|---|
| 挖空选择 | 从条文原文中挖掉一个关键词，生成 3 个干扰项 |
| 条文接龙 | 取条文上句/下句，四选一补全 |
| 方证匹配 | 给一组症状标签，选对应方剂 |
| 方剂组成 | 判断某药是否属于某方，或选出某方所含药物 |

### 4.2 选项策略

- 干扰项优先从同篇/同类数据中选取，避免一眼看出；
- 正确答案必须有原文依据；
- 每个选项保证不重复；
- 若自动生成选项不足，允许从同书其他篇补充。

### 4.3 确定性 ID

自动生成题不落盘，但 ID 必须稳定：

```
questionId = "AUTO." + stableHash(book + edition + sourceId + type + params)
```

- `stableHash` 使用 FNV-1a 32 位实现，纯 JS，无随机性；
- 同一内容、同一题型、同一参数，每次生成 ID 一致；
- 人工复核题 ID 为 `SHL.SB.Q.NNNN`，优先于自动题。

### 4.4 人工复核题覆盖

- 若某条文/题型存在 `questions.yaml` 中的 `reviewed` 题，则优先使用；
- 否则使用自动生成题；
- 错题本按 `questionId` 记录，因此自动题也必须依赖稳定 ID。

## 5. 搜索设计

### 5.1 索引内容

MiniSearch 索引字段：

| 分组 | 字段 |
|---|---|
| 条文 | 条文号、原文、白话译文、注解、主症标签名 |
| 方剂 | 方名、类方、组成药物名、相关条文原文 |
| 药物 | 药名、别名 |

### 5.2 中文分词

- MiniSearch 自定义 `tokenize`：对中文按**二字切词（bigram）**，对英文/数字按单词切分；
- 查询时同样对用户输入做 bigram 切分；
- 空格分隔多个关键词，默认 **AND** 语义。

### 5.3 索引与查询

- 内容为静态数据，索引在应用启动时构建一次；
- 索引构建与查询放到 **Web Worker**，避免阻塞 UI；
- 命中关键词高亮：在结果文本中定位原始关键词或 bigram 片段。

### 5.4 排序

1. 条文号顺序；
2. 命中字段优先级：原文 > 译文/注解 > 标签；
3. 命中次数多者靠前。

## 6. 备份格式

### 6.1 导出 JSON

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-01-01T00:00:00.000Z",
  "appVersion": "0.1.0",
  "data": {
    "settings": [],
    "studyPlans": [],
    "clauseStates": [],
    "cards": [],
    "reviewLogs": [],
    "dailyLogs": [],
    "quizLogs": [],
    "favorites": [],
    "wrongQuestions": []
  }
}
```

### 6.2 导入流程

1. 校验 `schemaVersion` 是否为当前支持版本；
2. 校验各表数据基本结构；
3. **先自动备份当前数据**（生成一个带时间戳的 JSON 下载）；
4. 确认后清空并写入导入数据；
5. 导入成功后刷新统计。

### 6.3 未来迁移

- 升级版本时保留旧 `schemaVersion` 的导入兼容；
- 迁移函数放在 `src/store/migrations.ts`。

## 7. 关键流程

### 7.1 每日任务生成

1. 取 `due <= 今天` 的卡片；
2. 取全部 active 计划（最多两个），按各计划分别取 N 条新条文；
3. 合并为今日队列；
4. 若超过 20 条，保留到期复习，新学顺延。

### 7.2 打卡

- 完成“全部到期复习 + 当日新学”后写 `dailyLogs`；
- 连续天数按 `docs/学习计划与统计口径.md` 计算。

### 7.3 错题进入错题本

- 刷题答错时写 `quizLogs`，并 upsert `wrongQuestions`；
- 错题重做正确后，可标记 `resolved = true`，但保留历史记录。
